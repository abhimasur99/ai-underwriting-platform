# Decisions

| # | Decision | Why | Revisit when |
| --- | --- | --- | --- |
| D1 | Use the plain `anthropic` SDK (single structured-output calls; see D17 for why there is no model tool loop), not Google ADK | Claude is the only model; one API key; we own the control loop and the event log. ADK would need LiteLLM or a Google Cloud setup for Claude and its own session and event model. | The team is on Google Cloud or Gemini, or we want ADK's built-in evals and dev UI |
| D2 | Do not use the Claude Agent SDK | It is built around coding-style agents with file and shell tools, which we do not need | Agents need open-ended tool use |
| D3 | React and Vite frontend with a FastAPI backend, not Streamlit | Better demo: React Flow can animate handoffs, docked chat and viewers are easier. Costs about 30 to 45 minutes more. | Time runs short; fall back per the cut line in `docs/sprints.md` |
| D4 | Hub-and-spoke: all handoffs go through the chief | One place for state, permissions, and audit; no agent-to-agent drift | Never for the MVP |
| D5 | The chief is a code state machine with a model only for chat intent and wording | Predictable, testable, cheap, explainable | Routing becomes genuinely ambiguous |
| D6 | The checker has its own deterministic tools and an independent parse and formula path | A checker that shares code with the underwriter repeats its bugs | Never |
| D7 | External UI is the chat only; chat reports checklist and status | Simpler; fewer screens to secure | Borrowers need document history |
| D8 | Deals tracker screen deferred | Not needed for the MVP demo | After the MVP |
| D9 | SQLite plus an append-only event log; queue is a view | Simple, auditable, enough for localhost | Multiple users or hosted deployment |
| D10 | Cached fixtures for every agent; `--live` calls Claude | Demo and CI work offline and are repeatable | Never |
| D11 | Thresholds live in `config/rules.yaml` and are labeled illustrative | The real lender's box is unknown | After discovery with the lender |
| D12 | Memo narrative uses number placeholders; code fills numbers; a test rejects stray digits | Models must not type numbers | Never |
| D13 | MVP uses the borrower's pro forma NOI and ARV as given | Keeps scope small | A real underwriting haircut is added |
| D14 | LTV is initial advance divided by as-is value; LTC and loan-to-ARV use the full commitment | Bridge convention with a renovation holdback | The lender defines it differently |
| D15 | Exit DSCR is stabilized NOI divided by (payoff times take-out rate); take-out max is the smallest of DSCR, LTV, and debt-yield caps | Tests whether the property can refinance out the bridge balance | The lender uses a different exit test |
| D16 | Rent roll vs T-12 gap above 10% is a decline reason; 5 to 10% is a watch reason | Data integrity failures should stop a deal | Lender tolerances are known |
| D17 | The underwriter and checker call their tools in a fixed order from code; the model gets single structured-output calls (narrative, wording), not a model-driven tool loop | The order is fixed by the spec, so a generic tool loop adds cost and failure modes without adding capability. Every tool call is still logged with inputs, formula and output. | An agent needs to choose its own tools |
| D18 | Chat reply text is composed by code from tool output; the model (or cached rules) only interprets a message into a typed turn | The external chat can never leak a number or a decision, and the chief can never state a figure it did not get from a tool. Both are tested. | We want freer conversational wording and can bound what it may say |
| D19 | Live calls use structured outputs (`output_config.format` JSON schema) with no `temperature`, no forced `tool_choice`, no prefill | `claude-sonnet-5-5` rejects non-default sampling parameters and forced tool choice with a 400. This supersedes "temperature 0" in `docs/agents.md` section 6; determinism comes from code owning the numbers, not from sampling. | The model or its API changes |
| D20 | Live extraction is the deterministic parsers only; Claude-assisted gap filling for unfamiliar documents is deferred | First item on the cut line in `docs/sprints.md`. Cached `extracted.json` and the parsers cover every sample deal. | Real, messy documents are in scope |
| D21 | Server-side refusal fallbacks are not enabled; a refusal fails the step loudly (`ModelRefusal`) | They need a beta header that cannot be tested without a key, and sample deal text is unlikely to trip a classifier. | A live run shows refusals on benign input |
| D22 | A deal's id is the platform's (`D-0001`...), set when the deal is created; the id inside the documents is ignored after extraction. The CLI reuses the document id (`D-0042`) for sample deals | A broker's document must not be able to choose or collide with an internal id | Deals arrive with trusted external ids |
| D23 | Demo pacing: `BRIDGE_STEP_DELAY` (seconds, default 0) makes each agent visibly "work" so the Flow tab is watchable; `BRIDGE_FORCE_MISMATCH=once\|persist` demos the retry loop from the UI. Both are environment settings, off in tests and CI | Offline runs finish in milliseconds, which makes a live Flow view meaningless. The pause is only a sleep after a handoff is sent; it changes no logic or result. | Never for the MVP |
| D24 | The frontend has no router, spreadsheet or PDF library: a hash router, the browser's PDF viewer in an iframe, `EventSource` for SSE, and a backend `GET /api/deals/{id}/workbook` that returns cells with their formulas and recalculated values (same safe evaluator the checker uses) | Fewer dependencies to approve, secure and explain. Added dev-only `openapi-typescript` for generated API types. | A feature needs more than these provide |
