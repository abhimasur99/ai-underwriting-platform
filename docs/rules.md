# Rules: formulas, decision logic, deterministic code

All thresholds live in `config/rules.yaml` (version `0.1-illustrative`, not any real lender's box). All formulas live in `backend/bridge/core/calc.py`. The checker re-implements them independently in `core/independent/`. Reference values for the three sample deals are in `data/deals/*/expected.json`, generated by `scripts/generate_sample_deals.py`.

## 1. Inputs used
`purchase_price`, `renovation_budget`, `loan_commitment`, `initial_advance` (commitment minus renovation holdback), `as_is_value`, `arv`, `note_rate`, `stabilized_noi` (borrower pro forma, used as given in the MVP), `in_place_noi` (from the T-12), sources and uses, rent roll, T-12.

## 2. Formulas (interest-only, no amortization)
| Metric | Formula | Notes |
| --- | --- | --- |
| total_cost | sum of uses (purchase price + renovation + any other uses) | MVP samples exclude closing costs and fees |
| ltc | loan_commitment / total_cost | |
| ltv_as_is | initial_advance / as_is_value | Bridge convention: holdback is not funded at closing |
| loan_to_arv | loan_commitment / arv | |
| dscr_in_place | in_place_noi / (initial_advance x note_rate) | Informational; usually below 1.0 on a transitional asset |
| debt_yield_stabilized | stabilized_noi / loan_commitment | |
| implied_cap_rate | stabilized_noi / arv | Flags aggressive ARVs |
| payoff | loan_commitment x (1 + exit_fee_pct) | Interest assumed paid current |
| dscr_cap | stabilized_noi / (min_dscr x takeout_rate) | Largest take-out the NOI supports |
| ltv_cap | max_ltv x arv | |
| debt_yield_cap | stabilized_noi / min_debt_yield | |
| takeout_max | min(dscr_cap, ltv_cap, debt_yield_cap) | Report which cap binds |
| refi_cushion | takeout_max - payoff | Negative means the bridge cannot be refinanced out |
| exit_dscr | stabilized_noi / (payoff x takeout_rate) | DSCR if the bridge balance is refinanced |
| stress | noi x (1 - noi_haircut); rate + rate_bump_bps/10000; recompute caps, cushion, exit_dscr | Default NOI -10%, rate +100 bps |

Reconciliation values:
- `rent_roll_annual` = 12 x sum of `monthly_rent` over occupied units (retail included).
- `t12_rental_income` = total of the "Gross rental income" line.
- `rent_roll_vs_t12_gap` = abs(rent_roll_annual - t12_rental_income) / t12_rental_income.
- `sources_vs_uses_gap` = abs(sum(sources) - sum(uses)) / sum(uses), computed from the component rows. Also flag if a stated total differs from its component sum.
- `unit_count_match`: stated unit count equals the number of rent roll rows.
- `in_place_noi` = T-12 total income minus total expenses.

## 4. Decision logic
Evaluate every rule, collect all reasons (do not stop at the first). Boundaries are strict: a value exactly at a threshold does not trigger.

| Reason code | Severity | Trigger |
| --- | --- | --- |
| ASSET_TYPE_NOT_ALLOWED | decline | asset type not in `eligibility.asset_types` |
| LOAN_SIZE_OUT_OF_RANGE | decline | commitment outside `loan_size_usd` |
| LTC_DECLINE / LTC_WATCH | decline / watch | ltc above 0.85 / above 0.75 |
| LTV_AS_IS_DECLINE / LTV_AS_IS_WATCH | decline / watch | ltv_as_is above 0.85 / above 0.75 |
| LOAN_TO_ARV_DECLINE / LOAN_TO_ARV_WATCH | decline / watch | loan_to_arv above 0.75 / above 0.65 |
| EXIT_DSCR_DECLINE / EXIT_DSCR_WATCH | decline / watch | exit_dscr below 1.10 / below 1.25 |
| REFI_CUSHION_NEGATIVE_BASE | decline | base refi_cushion below 0 |
| REFI_CUSHION_NEGATIVE_STRESS | watch | base cushion not negative but stress cushion below 0 |
| IMPLIED_CAP_RATE_LOW | watch | implied cap rate below 0.05 |
| RENT_ROLL_VS_T12_DECLINE / _WATCH | decline / watch | gap above 0.10 / above 0.05 |
| SOURCES_VS_USES_DECLINE / _WATCH | decline / watch | gap above 0.01 / above 0.005 |
| UNIT_COUNT_MISMATCH | watch | stated units differ from rent roll rows |
| LOW_CONFIDENCE_FIELD | watch | any key field with confidence below 0.80 (one reason per field) |
| MISSING_REQUIRED_FIELD | none (blocks) | stops the run and returns NEEDS_INPUT; never defaulted |

Call: `decline` if any decline reason; else `watch` if any watch reason; else `screen`. Each reason carries its inputs (value, threshold, source field) so the memo and UI can show the arithmetic. Sample answers: Bronx has no reasons (screen); Queens has `REFI_CUSHION_NEGATIVE_STRESS` (watch); Brooklyn has `LTC_DECLINE`, `LTV_AS_IS_DECLINE`, `LOAN_TO_ARV_DECLINE`, `EXIT_DSCR_WATCH`, `REFI_CUSHION_NEGATIVE_BASE`, `RENT_ROLL_VS_T12_DECLINE`, `SOURCES_VS_USES_DECLINE` (decline).

## 5. Completeness (code)
Documents are satisfied when at least one file is labeled with each required type in `config/checklist.yaml`. Facts are satisfied when the chat recorded them or extraction provided them. Output: `{required: [...], received: [...], missing: [...], ready: bool}`. Classification order: filename hints, then header hints, then (internal model, enum only) a label.

## 6. Parsers (MVP sample formats)
- `rent_roll.csv`: columns `unit, unit_type, sqft, status, tenant, lease_start, lease_end, monthly_rent`. Accept common synonyms (`rent`, `monthly rent`, `apt`). Status values: occupied, vacant.
- `t12.csv`: columns `line_item, category, 2025-11 ... 2026-10, total`. `category` is income or expense. Verify `total` equals the sum of months; mismatch is a flag.
- `renovation_budget.csv`: `line_item, amount`; sum must equal the stated renovation budget or flag.
- `deal_summary.md` and `purchase_contract.md`: deterministic parse of `Label: value` bullets and markdown tables for the samples. Live mode sends the text to the extraction agent for general documents.
- Every parsed field records `{doc, locator}`: file name plus row, column, or line range.

## 7. Workbook layout (`openpyxl`, live formulas)
Sheets: `Summary` (call, reasons), `Inputs` (every field, value, source), `Rent Roll`, `T-12`, `Sources & Uses`, `Metrics` (Excel formulas referencing `Inputs`), `Exit & Stress` (formulas for caps, cushion, stress), `Flags`. Metric cells must be formulas, not pasted numbers; the checker audits this.

## 8. Memo layout (one page, `reportlab`)
Header (deal id, name, date, call). Recommendation and the top reasons. Deal snapshot (property, request, sources and uses). Metrics table (value, threshold, status). Exit analysis (three caps, binding cap, cushion, stress). Reconciliation and flags. Open questions. Footer: "Sample data. Illustrative thresholds, not a real lender's box. A human approves every decision."

Narrative text comes from the underwriter agent with placeholders such as `{{metrics.ltc}}` and `{{exit.takeout_max}}`; code renders them. Any digit outside a placeholder in the narrative fails validation.
